Networking / CASE STUDY

Networking, DNS & remote access

A lot of my network learning has come from trying to work out why something doesn't connect or why a service behaves differently from one device to another.

OperationalIndependent project
Why I did it

Get predictable local connectivity and a safe way to administer my services without opening unnecessary internet-facing ports.

What I configured / built
  • Configured the ASUS router to use a Pi-hole Debian VM for DNS and checked its query logs.
  • Investigated double NAT between the FibreNest/Adtran ISP gateway and the ASUS router, including how it affects inbound connections.
  • Configured an Aruba managed PoE switch and tested the wired route between the router, switch and PC.
  • Set up Tailscale for private remote connectivity and used SSH for administration.
What I verified
  • Confirmed DNS queries were reaching Pi-hole and filtering was taking effect.
  • Measured around 850 Mbps on a wired speed test after troubleshooting the switch connection, against an 800 Mbps fibre service target.
  • Tailscale and SSH were configured for remote device management.
What I learned

Checking the actual route, DNS behaviour and test results is far more useful than changing settings at random.

Current status / next steps

Continue working through ISP limitations for game hosting that needs external inbound access.
